# My Company Brain 自有能力覆盖台账

## 1. 证据状态与处置规则

每个功能编号必须且只能出现一次。当前能力状态使用四级证据词汇：

- **已实现**：代码、配置或文档中存在对应能力，但不代表自动化或真实环境验收已通过。
- **已自动验证**：有可重复的本地测试、类型检查或静态检查证据。
- **已真实环境验证**：在当前真实服务、数据库、容器或主机端点上完成了对应检查。
- **待验证**：当前证据不足以推出通过，必须保留为未验收状态。

“负责人决策”和“移除”是处置记录，不属于验收证据状态。只有明确的负责人决策才能改变产品行为或删除编号。279 个编号仍然完整保留；本表不再用单一完成标记替代证据。

## 2. 分层能力范围

| 区域 | 必须保持的结构与行为 | 自有实现边界 |
|---|---|---|
| web | 39 个页面、五态、动作、导航、登录与角色跳转 | 只访问统一 API 与 Agent Gateway |
| api | 身份鉴权、请求归一化、模块健康与 HTTP 分发 | 不读取或写入任何模块数据库 |
| agent-gateway | LangGraph 会话、SSE、MCP、检查点、人工审批边界 | 使用 mcb_agent_db；工具调用遵守模块权限 |
| nano-brain | 知识页、原始文档、四类产物、事实复核、链接、自治运行 | 使用 mcb_nano_db，按来源和成员过滤 |
| traditional-rag | 文档与表格入库、任务、三路串行召回、RRF 与可解释分数 | 使用 mcb_traditional_db |
| graph-rag | LightRAG 文档、工作区检索、问答、实体关系治理 | 使用 mcb_graph_db 与 Neo4j |
| packages/platform | 场景、任务、知识对象、审批、审计、运行配置、全域编排与重排 | 使用 mcb_core_db；不侵入模块内部检索 |
| deploy | 六库、角色、迁移、八服务、网络、卷、健康、恢复与重置 | 默认仅暴露 web，观察端口限本机 |

## 3. 数据、检索与运行一致性

- 六个 PostgreSQL 数据库物理隔离；运行角色只能访问所属库，迁移角色集中执行受控 DDL。
- Traditional RAG 的关键词、trigram 字面和向量召回在模块请求内串行执行；RRF K=60，阈值只比较全候选最大 RRF 归一化分。
- Nano Brain 保持关键词、向量、事实关键词、事实向量和链接扩展；GraphRAG 保持工作区隔离的 LightRAG 与图存储。
- 全域重排只属于平台层；可选重排密钥缺失时保留全部候选。
- 权限过滤位于各模块 SQL 查询边界；普通成员只可读公开、本人私有及团队交集，管理员拥有管理权限。
- 引用、会话记忆、MCP 工具、检查点、审计及人工审批门禁均为强制能力。
- Compose 包含八个持续健康服务与一个成功退出的一次性迁移任务；恢复不得覆盖非空数据，重置必须显式确认。
