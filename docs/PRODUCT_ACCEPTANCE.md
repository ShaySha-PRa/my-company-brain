# My Company Brain 产品验收目标

状态：产品体验基准；验收证据以 [当前状态](CURRENT_STATUS.md) 为准

## 1. 产品目标

My Company Brain 必须表现为企业级聚合知识库，而不是 RAG、Graph、Agent 的调试控制台。

用户进入系统后，应先看到业务任务：

- 记录一条知识。
- 上传一份资料。
- 录入一段关系资料。
- 向知识库提问。
- 审核公共知识。
- 处理知识库运行风险。

底层技术对象只能服务这些任务，不能成为普通用户理解和使用系统的前提。

## 2. 核心用户

### 企业员工

企业员工使用系统完成日常知识消费和贡献：

- 把个人记录、会议纪要、客户线索写入自己的知识空间。
- 上传文档并查看是否可以检索。
- 提问并获得答案、证据和引用来源。
- 向公共知识库提交需要沉淀的事实线索。
- 看懂失败原因和下一步动作。

企业员工默认不应看到或必须理解：

- slug。
- chunk。
- embedding。
- workspace。
- raw text。
- dry-run。
- 出链、反链。
- MCP、SSE、tool trace、checkpoint。
- Run ID、Source ID、Document ID 等内部标识。

### 企业知识库管理员

知识库管理员负责治理和维护三条独立知识链路：

- 管理公共知识空间和权限边界。
- 审核事实线索并写入公共事实库。
- 查看文档处理失败、关系资料写入失败和维护任务风险。
- 使用高级诊断信息排查问题。
- 复盘 Agent 运行过程，但不把技术审计作为普通问答主界面。

管理员可以访问技术字段，但这些字段必须位于高级诊断、审计详情或折叠区域中，不能压过主工作流。

### 角色分流

员工端和管理员端必须严格分流：

- 员工使用 `/facts` 提交事实线索并查看自己的提交状态。
- 知识库管理员使用 `/facts/review` 审核事实线索并维护公共事实库。
- 同一页面不得同时承载员工提交和管理员审核操作。
- 直接访问不属于当前角色的页面时，必须回到该角色对应的工作区。
- 导航和总览入口必须按角色展示，不能让员工主路径出现管理员操作入口。

本轮角色路由边界：

员工工作区：

- `/sources`：员工知识空间。
- `/pages`：员工知识页面。
- `/explore`：记录知识与可信问答。
- `/facts`：事实线索提交。
- `/traditional`、`/traditional/documents`、`/traditional/search`、`/traditional/tables`：员工资料空间、上传、证据检索和表格查询。
- `/graph`、`/graph/documents`、`/graph/search`：员工关系空间、关系资料录入和关联发现。
- `/agent`：员工知识问答。

管理员工作区：

- `/sources/admin`：公共知识空间治理。
- `/facts/review`：公共事实审核。
- `/dream`：知识质量巡检与维护。
- `/traditional/admin`、`/traditional/admin/documents`、`/traditional/jobs`：公共资料空间治理、公共资料维护和全局处理状态。
- `/graph/admin`、`/graph/admin/documents`：公共关系空间治理和公共关系资料维护。
- `/agent/audit`：知识助理运行审计和管理员审核辅助。

## 3. 三条链路的业务表达

### Nano Brain

默认表达：

- 个人知识。
- 公共知识。
- 记录知识。
- 可信问答。
- 事实线索。
- 相关知识。

技术表达只允许出现在高级诊断：

- slug。
- chunk。
- embedding。
- 出链、反链。
- 关系图。

### Traditional RAG

默认表达：

- 文档库。
- 上传资料。
- 处理状态。
- 文档证据。
- 表格查询。

技术表达只允许出现在高级诊断：

- hybrid search。
- RRF。
- chunk。
- parser metadata。
- document/source/job 内部 ID。

### GraphRAG

默认表达：

- 关系知识库。
- 录入关系资料。
- 关联发现。
- 关系依据。
- 引用来源。

技术表达只允许出现在高级诊断：

- raw text。
- LightRAG workspace。
- graph mode。
- context。
- workspace ID。

### Agent

默认表达：

- 知识助理。
- 能力范围。
- 回答。
- 依据。

技术表达只允许出现在运行审计：

- SSE。
- tool call。
- checkpoint。
- trace。
- run event。

## 4. 产品验收标准

1. 员工从首页或总览进入系统时，可以按任务选择链路，而不是按技术模块猜入口。
2. 员工主路径不出现必须理解的技术黑话；如因兼容保留英文术语，必须有业务化名称作为主标签。
3. 管理员能找到治理和诊断能力，但默认工作区仍以业务决策为中心。
4. 三条链路在健康状态、导航和入口中地位一致。
5. Source、Workspace、Run、Chunk 等内部对象不得作为默认页面的主要标题或主要按钮。
6. 内部 ID、原始 JSON、工具事件必须放入“高级诊断”或“运行审计”折叠区。
7. 失败状态必须告诉用户业务影响和下一步动作，例如模型配置不可用、处理服务未启动、资料还不能检索。
8. 示例数据必须像真实企业资料，避免 `fixture42`、`smoke`、`api`、随机 UUID 这类测试痕迹成为默认可见内容。
9. 员工端和管理员端必须严格分流，普通员工不能在主路径看到或触发管理员审核动作。
10. 前端变更必须通过 Playwright 检查关键页面布局，确认文本不重叠、主入口可见；本轮事实审核页验收以桌面端为准。
11. 如果改动后端链路或接口语义，必须用 HTTP 接口进行功能实测。

## 5. 持续改进计划

1. 建立业务语言映射，把主导航、总览、Nano、Traditional、GraphRAG、Agent 的默认标题和按钮改成业务任务语言。
2. 新增高级诊断展示组件，把内部 ID、JSON、工具事件、处理细节折叠起来。
3. 优化 Nano 采集与问答页，隐藏 slug/出链/反链等默认暴露，改为“页面地址自动生成”“相关知识”。
4. 优化 Dream 与 Agent 页面，把 dry-run、SSE、tool trace 等技术词降级到高级区域。
5. 调整系统健康，三条链路同等展示，并提供清晰故障提示。
6. 更新前端文案后运行类型检查和 Playwright 布局验证。
